# Cross-build for EmberBSD

Build target programs on the development host.
Use the selected compiler from the EmberBSD SDK profile. Clang/LLVM is the
default; choose GCC only when the target profile requires it.
Use the matching [SDK sysroot](https://github.com/oxtech-ember/EmberBSD-SDK/blob/main/docs/sysroot.md).

The sysroot must contain EmberBSD headers, CRT, libc, libm, libpthread, libprop,
and the common Lua 5.5 and libcurl dependencies. Bluetooth Classic support is enabled by
default and additionally needs the OS Bluetooth headers and library. A target
without that service can set `SPARK_ENABLE_BLUETOOTH=no`; its build does not
register the Bluetooth or OBD modules.
Keep the compiler, ABI, runtime, and dependency set consistent.
Do not substitute upstream NetBSD components.

## Build and package

Set the selected target sysroot and compiler driver. Provide the unmodified
dkjson 2.11 source file from common Ports; the script verifies its SHA-256
before packaging it. The common Lua 5.5 and libcurl must already be installed
in the sysroot. Dynamic linking is the default; use
`SPARK_LINK_MODE=static` for a static executable and static pkg-config
dependencies.

```sh
export SPARK_TARGET=aarch64
export SPARK_SYSROOT=/path/to/emberbsd-aarch64/sysroot
export SPARK_CC=/path/to/toolchain/bin/aarch64--netbsd-clang
export SPARK_MAKE=/path/to/host-pkg-llvm/bin/bmake
export SPARK_PKG_CONFIG=/path/to/host-pkg-llvm/bin/pkg-config
export SPARK_HOST_LUA=/path/to/host-pkg-llvm/bin/lua5.5
export SPARK_READELF=/path/to/host-pkg-llvm/bin/llvm-readelf
export SPARK_DKJSON=/path/to/host-pkg-llvm/share/lua/5.5/dkjson.lua
scripts/build-emberbsd.sh
```

The output is `build/emberbsd-$SPARK_TARGET/`. It includes the executable, source
modules, version, licenses, and an ELF dependency list. Set `SPARK_BUILD_DIR` for another
absolute output directory. Set `SPARK_MAKE` if GNU Make has another name. Set `SPARK_READELF` if
the selected host `readelf` has another name.
The host needs a Lua 5.5 interpreter for source packaging; set
`SPARK_HOST_LUA` if it has another name. No target executable runs on the host.
The target links to the common Lua library (dynamically or statically as
selected). The package contains `agent-lua`, the compatible `oxtorg-agent`
symlink, bundled Lua modules, and `board-selftest.lua`; it does not contain a
second Lua runtime. Dynamic builds also require `SPARK_AWK` to name the
selected host awk used to list ELF dependencies.

## Package source modules

Use the host's Lua 5.5 interpreter and the selected dkjson source:

```sh
lua5.5 package.lua /path/to/dkjson.lua spark-development \
  build/emberbsd-$SPARK_TARGET/oxtorg-agent.lua lua/*.lua
```

These are source modules, not host-generated bytecode.
The device needs the selected runtime libraries and TLS trust roots.
Keep dependency licenses with a distributed package.

Record the source revision, compiler, sysroot provenance, flags, and output hashes.
Inspect the ELF architecture with the toolchain's `readelf`.
Compilation, target execution, and physical-device acceptance are separate results.
The previous GCC16 AArch64 build and board launch passed with the common Lua
5.5 ABI. RISC-V32 output still needs target execution and board acceptance.
See [target checks](testing.md#target-checks) for the fixture boundary.
